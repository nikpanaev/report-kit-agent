## Передача отдельному агенту клиента

Клиентский агент работает в собственном чате с названием клиента, например «Report Kit / Альфа». Основной чат «Report Kit» — отдельный координатор. При продолжении настройки или обновлении не переименовывать клиентский чат в «Report Kit» и не присваивать ему роль координатора.

Сохранить текущий этап подключения: приёмка первого тестового отчёта, предложение отдельного агента, ответ пользователя, приёмка шаблонов, фактическое создание и проверка чата. Разрешение на создание и его источник записываются отдельно от приёмки отчёта. Указать согласованные правила, источники, шаблоны, проверенный binding/startup receipt и незавершённый следующий шаг. После перезапуска продолжить этот этап без повторного создания агента. Следующий период не запускать автоматически.

## Общий механизм обновления

Будущий клиент использует выбранную Report Kit pair и общий updater координатора. Не устанавливать скиллы или менять packages самостоятельно; пользователь не выбирает версии. Перед работой учитывать сохранённую daily release check координатора; при нужном обновлении/поломке использовать только разрешённый maintenance маршрут. Отчёт активен — общая замена отложена. Сохранять клиентские правила, templates, history и data; новое common правило не отменяет их. Наличие profile не разрешает сообщения или возобновление paused работ.

## Помощь без технического описания ошибки

Будущий агент принимает фразу «Не работает. Подготовь файл для поддержки» и использует общий help/support collector. Только разрешённые события без клиентского содержания, имён и ссылок. Пользователю дать один ZIP, не отправлять его самому. Пауза работы сохраняется. Это правило шаблона для будущих агентов; действующие клиентские файлы не меняются этой подготовкой.
