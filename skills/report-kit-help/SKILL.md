# Помощь сотруднику

Для общего запроса «помощь» используй [краткую помощь](../../docs/HELP.md); для начала работы — [руководство](../../docs/USER-GUIDE.md). Читай только разделы, связанные с вопросом. Отвечай простым русским языком: конкретное действие, зачем оно нужно и какой результат ожидать. При общем запросе предложи несколько доступных задач; не перечисляй внутренние схемы и технические проверки.

Различай функции этого исходного комплекта и фактически установленные/проверенные функции устройства. При вопросе о текущем состоянии используй разрешённые локальные результаты; наличие инструкции не доказательство доступа, установки или успешного отчёта. Не читать чужие клиентские папки для справочного ответа.

Запрос «как сделать» означает объяснение. Прямое поручение выполнить работу направляй в соответствующий доступный workflow с его текущими полномочиями; сохраняй паузы и уже данные ответы. Для ошибки прочитай нужную часть [сопровождения](../../references/maintenance.md), не запрашивай секреты и не отправляй обращение без разрешённого маршрута.

Если инструкция расходится с наблюдаемым поведением, назови расхождение и подготовь локальное замечание сопровождающему. Не придумывай отсутствующий URL, функцию или успешную проверку. Внешнюю публикацию замечания согласовать отдельно.
