# Подключение нового клиента

Прочитай [workflow](../../references/workflow.md) и выбранные workspace settings; не искать клиентов в соседнем проекте. Проверить own client registry, не создавать дубль. При отсутствии workspace использовать [setup](../report-kit-setup/SKILL.md).

Веди [опрос по этапам](../../references/onboarding.md): название, нужный формат Google Презентации/Документы/Таблицы, образец, месяц+год, площадки/данные, папка и выбранный аккаунт. Извлекай остальные правила из образца сам и спрашивай только неясное. Не проси сотрудника подготовить technical registry/IDs. «Пилот» объясняй как первый отчёт по образцу; вторую проверку как согласованный следующий период. Report/base approval остаются раздельными.

Уточнить название/период/year, existing folder, образец, площадки/источники, правила слайдов/таблиц, сравнение/метрики, content/dedup/moderation, защищённые зоны и владельца приёмки. Сохранить ответы. Полностью inventory/review образца; нет доступа — exact coverage и зависимый шаг BLOCKED.

Записать только новый client profile в выбранной private workspace, используя [структуру](../../assets/client-profile.md). Факты, owner decisions и questions разделить; подтвердить синтез до зависимого пилота. Не заполнять generic defaults реальными ID или чужими клиентскими особенностями.

Пилоты — по workflow и новым source skills, только заданные периоды/бюджеты/accounts. Поздние счётчики не подгонять к образцу. Приёмка пилота не принимает отдельный шаблон: сформировать neutral monthly/cumulative roles этого клиента, реальный registry schema3/approval, pre-copy guard и отдельную приёмку exact base.

Первый тестовый отчёт готовится в общем чате Report Kit. После его явной приёмки сам предложи подготовить шаблоны и отдельного агента клиента по [порядку передачи](../../references/onboarding.md#первый-результат-и-переход-к-обычной-работе). Не жди отдельной догадки пользователя. Проверь профиль: уже выполненное предложение или создание не повторять; после перезапуска продолжить незавершённый шаг.

Клиентский агент работает в отдельном чате с названием клиента, например «Report Kit / Альфа», с собственным профилем, согласованными правилами, шаблонами и источниками. Основной чат «Report Kit» остаётся для подключения клиентов и общих вопросов. Создавай клиентский чат только с прямого разрешения пользователя после оговорённых приёмок; уже полученное разрешение повторно не запрашивай. Новый binding, actual target/cwd и startup receipt проверить; delivery не completion. Следующий период проводится в чате клиента только по отдельному поручению. Никаких schedules. После приёмки убрать task temporary files по workflow, сохранив источники/историю.

Перед новой работой используй [общий единый порядок обновлений](../../references/updates.md): координатор проверяет published releases не чаще24ч и полную совместимость всех клиентов. В клиентской роли используй сохранённый coordinator check и разрешённый maintenance маршрут; не читай чужие профили и не устанавливай пакеты сам. Обновление только между заданиями, без изменения клиентских правил и истории. Новые client profiles получают этот же общий механизм.
