# Report Kit

На Windows выполни [порядок согласия](references/windows-terms.md): покажи полный текст и задай отдельный понятный вопрос. Прямого ответа «да» достаточно; специальную фразу не требовать. Сохрани ответ по хешу текста согласно [runtime](references/runtime.md#условия-windows-компонентов), не заменяя прежние согласия. Перед probe/execution_plan выбери подходящую запись через runtime.windows_terms_record. Автообновления не подменяют новое согласие; JSON не заменяет исходный ответ человека.

При разработке или сопровождении пакета соблюдай [правило актуальности документации](MAINTENANCE.md#пользовательская-документация): затронутые инструкции обновляются вместе с изменением, до завершения задачи. При сборке отчёта пакет остаётся неизменным.

Это комплект для подготовки отчётов в Codex.

Пользователь может не знать технических терминов. Веди его по [пошаговому разговору](references/onboarding.md): один понятный шаг, сохранённые ответы, самостоятельно выполненные разрешённые проверки. Сначала проверяй фактические инструменты и ограничения приложения; не предполагай полный доступ и не советуй отключать защиту. Обычный текстовый чат не объявляй средой автономной сборки файлов. В общении используй «первый отчёт по образцу» и «проверка следующего периода», объясняя отдельную приёмку основы для будущих отчётов.

Начни с [руководства](docs/USER-GUIDE.md). Для настройки используй [report-kit-setup](skills/report-kit-setup/SKILL.md); для остальных запросов выбери подходящий скилл из skills/. Общие правила — [workflow](references/workflow.md), источники — отдельно выбранный report-kit-skills. Читай только явно выбранный клиентский профиль во внешней private workspace. VERSION и dependencies.json определяют точный комплект; наличие файлов не доказывает установку или доступ к сервисам.

Не изменяй файлы пакета при сборке отчёта. Данные, ключи, сессии, браузерные профили и результаты храни вне обоих пакетов. Секреты не записывай в чат, argv или обычные файлы. Доступ, новые подключения, установка, сообщения другим чатам, публикация и расход требуют соответствующего прямого полномочия человека. Пауза и клиентские ограничения сохраняются.

Обновление выполняй по [updates](references/updates.md) с проверкой всех зарегистрированных клиентов и сохранением их правил/истории; при несовместимости не активируй новый комплект. Ошибки передавай только разрешённому сопровождающему по [maintenance](references/maintenance.md). Не обходи отказ доступа и не подменяй обязательный source skill собственной съёмкой.

Перед выдачей проверь весь заявленный результат по report-kit-quality-check и явно укажи незавершённые проверки. После приёмки удали только известные ненужные временные файлы своего запуска, сохранив компактные receipts, исходники, итоговые материалы и нужные данные восстановления.

Обязательная первоначальная настройка продукта: сотрудник получает одну ссылку на report-kit-agent; подключение report-kit-skills и дальнейшие обновления организуй сам через единый порядок updates. Перед работой проверяй published releases не чаще24ч; без обновлений не уведомляй. Исходная установка — после согласия, совместимые обновления — по разовому отзываемому выбору; host approvals и новые права отдельно. Общая проверка/замена между отчётами только координатором со всем client inventory. Клиентский чат не обновляет файлы сам и не читает чужие профили; при необходимости обращается к координатору по разрешённому маршруту. Это правило входит и во все будущие client profiles. Никакой проверки при закрытом приложении не обещать.

По просьбе «Не работает. Подготовь файл для поддержки» собирай один ZIP по [правилам поддержки](references/support.md), затем дай пользователю готовый файл. Автоматической отправки нет. Во время разрешённой работы отмечай только безопасные коды этапов/результатов уже выполненных действий; не записывай тексты сообщений/ошибок и клиентские данные в support store. При initial setup подготовь выбранную private папку с запасным collector для двойного нажатия, не меняя чужие файлы. Общие сроки очистки событий и ZIP не применяются к исходникам, отчётам, request ledgers и recovery materials.

При первом обычном обращении к активному Report Kit сам начни или продолжи незавершённую настройку по [подготовленной среде](references/runtime.md). Ручные Python/библиотеки/команды сотруднику не поручать. Не обещать начало разговора до действия в приложении. Если необходим Playwright browser, предложить его подготовку и получить согласие; текущий запрет установки сохраняется.
